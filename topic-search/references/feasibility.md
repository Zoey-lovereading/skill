# 可行性与定题

输入来自前序流程：学科或领域、核心问题、文献表、查新结果、拟用设计。还需了解实际资源：已取得或明确可取得的材料、权限、技能、经费、指导和截止时间。信息不全时区分已确认、暂定和未知，只追问能改变判断的少数条件。

先明确产出目标（描述、关联、因果、机制解释、证明、方法验证等），找最接近的同类研究核对证据要求。可行性由问题和设计决定，不套统一样本量、工期和评分。参照不足时标明待核实。

| 类型 | 典型硬条件与最小验证 |
|---|---|
| 定量观察 | 关键指标能可靠测量，样本覆盖关键比较，数据可匹配。用小批真实数据核对时空口径、匹配率、缺失和分组覆盖。因果问题另核对对照与识别假设。 |
| 实验 | 材料设备和适用审批可落实，核心条件可控制，预实验能稳定测量目标结果。 |
| 质性或田野 | 获准进入现场，能接触关键对象并取得足够丰富的材料。先核实进入和招募渠道；需要审批的工作须在获准后实施。 |
| 历史或文献 | 关键史料能取得、解读和交叉印证。先验证代表性材料可调阅、关键时期覆盖足以支持论证。 |
| 理论或数学 | 假设明确，证明路径或反例有着落。先攻关一个决定后续的引理，说明失败时怎样缩小命题。 |
| 工程或计算 | 原型、数据、基线和评价条件可获得。先跑通一个最小基线或验证一个关键模块。 |

推荐输出：**必要条件｜依据｜已有资源｜判断｜验证办法**。将不可替代条件放前面。最小验证要写明任务、通过标准和失败后的缩题方案；试跑只能说明流程或条件是否有起色，不能用小样本显著性代替正式验证。最后给出一个明确建议：可定题、先验证再定题、缩题后可做，或当前不宜做；注明最优先确认的一个事项。
