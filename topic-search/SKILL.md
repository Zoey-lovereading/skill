# Topic Search：从上传论文到确定选题

目标是得到一个值得回答、有明确增量、能用现有条件可信回答的问题。区分四件事：**方向**是研究范围，**候选问题**是可选择的研究任务，**空白**是已有证据仍未回答的部分，**贡献**是新研究预计增加的知识或能力。选题时可承诺要检验什么，不预告一定会得到什么结果。

## 如何带用户走完整个流程

用户启动完整流程但还没给材料时，第一条回复直接引导上传手头最相关的几篇论文 PDF 或全文；补充材料可一并上传，先给一篇也可以。告诉用户收到后就会逐篇解析并生成文献表。已有附件就直接开始；已有可靠的文献表、候选题或查新结果时，从相应阶段接续。

每阶段先交付实际产出，用“第 N 步：……”标明进度，并说清它如何用于下一步。用户需要选择方向时，给出有理由的推荐和备选；需要确认资源时，只问会改变结论的关键信息。若用户明确要求逐步确认，在这些决策点等其选择；用户委托代选且所需材料齐全时，继续推进。不要用流程介绍代替实际工作，也不要每一步都要求确认。到定题建议为止；若关键条件没有核实，清楚交代下一项需要做的验证。单独索要方法或指令时，可用[可复制指令](references/prompts.md)提供对应内容。

1. **接收原始论文，逐篇解析，再生成文献表。** 这是没有现成文献表时的默认入口。请用户上传手头的论文 PDF、补充材料或提供全文；已有附件就直接读取，无需用户预先总结或建表。先按论文区分材料，阅读研究问题、方法、结果、图表和相关附录，核对实际测量了什么、做了什么比较、结论能推到哪里。随后把各篇解析结果汇总为统一的[八列文献表](references/evidence-table.md)，直接交付可核对的表格；需要粘贴到 Excel 时可给 TSV。关键事实附原文位置；仅有摘要、部分不可读或缺附件时，标明能核实的范围，不能凭标题或常识补齐。用生成的表继续下一步。
2. **横向比较，圈定方向。** 把回答同一问题或研究同一现象的论文放在一起，找共同结论以及它们合起来还回答不了哪一步。核对指标、分析单位、设计和证据是否可比；一篇论文的局限可能已被另一篇补上。也可从真实决策所缺的依据反推方向，并用文献确认。把推荐方向和备选方向给用户看，各自指出依据与待确认点。
3. **将方向拆成备选问题。** 围绕同一现象追问：换情境还成立吗？在哪些条件下不同？为何发生？现有证据能说明关联还是因果？选择有依据的追问，分别写成具体问句，注明价值、可能增量和所需的最低证据。几个候选是供选择的不同任务。换地区或扩大样本本身是覆盖拓展；说明它能检验什么边界、发现什么规律，或满足什么本地需求。
4. **反向查新，更新原表。** 把新意写成可被已有论文推翻的主张，先明确什么算直接回答。以表中反复出现的概念宽搜，再用候选问题的关键条件定向找最可能撞题的原始研究。用中英文同义词、替代指标、上位地区或多地区研究和引文追踪补漏；核对方法、结果与附录中的关键比较。记录实际平台、检索词和最接近文献的出处；仅见摘要标明，无法联网则给检索式并注明尚未检索。区分已有直接证据、部分覆盖、本轮未找到直接证据。把新证据补回表，必要时撤回或缩小主张；未检出不能证明“首次”。
5. **按学科和设计做可行性审查。** 在确定问题、结论目标和最接近同类研究后，核对数据或材料、测量、设计、方法与支持、时间经费、适用的伦理与权限。优先列会卡住题目的硬条件，区分已确认、暂定、未知；不要用总分掩盖硬缺口。根据 [可行性与定题](references/feasibility.md) 选择一个最小验证任务及通过条件，给出可定题、先验证、缩题后可做或当前不宜做的判断。

完整流程交付：根据所给论文生成或补充的文献表、候选问题和表内依据、最接近的表外反例及新意判断、排序理由、可行性判断和定题前最优先的实际验证。将研究价值、创新性和可行性分开；证据未核实时说明判断的范围。
